# CLI: реестр и проверка переходов

`tools/pipeline.py` работает на Python 3.10+ без внешних библиотек. Сетевых запросов, вызовов моделей и генерации игры в нём нет: агенты выполняют работу, CLI проверяет записанный пакет и порядок решений. Единственный писатель `run.json` — оркестратор. Субагенты возвращают отдельные файлы, которые он регистрирует последовательно.

## Команды

| Команда | Что делает |
|---|---|
| `init --run pilot-20261111-01 --through G2` | Создаёт пустой прогон до G2; без выбора игры |
| `status --run pilot-20261111-01` | Показывает текущий gate, маршрут и недостающие ревью |
| `audit --run pilot-20261111-01` | Пересобирает состояние из истории, проверяет хэши и утверждения |
| `validate-research --run pilot-20261111-01` | Проверяет форматы, ссылки между записями и дедупликацию |
| `propose --run pilot-20261111-01 --manifest artifacts/G0-v1/proposal.json` | Регистрирует конкретную версию пакета, сбрасывает ревью прежней версии |
| `review --run pilot-20261111-01 --file reviews/G1-evidence-v1.json` | Регистрирует реальный отзыв независимого субагента |
| `approve` | Проверяет готовность, записывает настоящий ответ и переходит дальше |
| `decide` | Фиксирует `revise`, `back`, `hold`, `stop`, `resume` |
| `extend` | После завершения расширяет согласованную границу G2→G9 либо G9→G11 |
| `check-repo` | Проверяет комплектность маршрутов, файлов и схем |

Справка точных аргументов доступна через `python3 tools/pipeline.py approve --help` и аналогично для каждой команды. Ошибка проверки возвращает exit code `2`; успешная операция — `0` и JSON.

## Пакет предложения

Сначала создать материал этапа, затем manifest по `schemas/proposal.schema.json`: текущий `gate`, реальные `author_ids`, `files`, краткий `summary`, варианты `options` с постоянными `id` и читаемыми `label`, `is_synthetic: false`. Полный учебный пример находится в `examples/`; его синтетический флаг запрещает использовать его в действующем прогоне.

Все пути относительны папке run. В manifest перечислить **все существенные файлы**: карточку, источники, изображения, исходники/сборку прототипа, результаты проверок. Для G1 обязательны `evidence.jsonl`, `signals.jsonl`, `clusters.json`, `opportunities.json`; `options.id` совпадают с тремя `territories.id`. G2 и G6 требуют три варианта.

`propose` считает SHA-256 байтов manifest и каждого перечисленного файла, сортирует пути и считает общий SHA-256 от канонического JSON. Хэш всего пакета используется как `artifact_sha256` в ревью и `proposal_sha256` в решении. Копия исходных файлов остаётся в `snapshots/<sha256>/` даже после возврата. Создавайте новую версию в новом каталоге, чтобы прежняя оставалась читаемой.

**Граница проверки:** CLI контролирует перечисленные файлы. Он не обнаруживает автоматически внешние зависимости, смысловую полноту GDD и пропущенные вложения; это проверяют автор и независимые ревьюеры. Новая сторонняя ссылка не фиксирует содержимое страницы во времени — значимые данные нужно сохранять локальным наблюдением с датой и источником.

## Ревью и пользовательские решения

`review` принимает JSON по `schemas/review.schema.json`. `run_id`, `gate` и хэш должны совпадать с текущим предложением. На каждом обязательном гейте у каждой линзы — отдельный `reviewer_id`, которого нет среди `author_ids`. `NOT_RUN`, `BLOCKED`, `CHANGES_REQUIRED` закрывают переход. Критическое замечание нельзя заменить принятием риска; серьёзное замечание допускает явно документированное принятие пользователем.

Каждый файл ревью регистрируется один раз: новое заключение получает новый путь. `audit` проверяет оригиналы отзывов и архивные копии, а также все старые пакеты из истории после возвратов. Для повторного `PASS` той же версии каждый прежний открытый `critical`/`major` должен явно присутствовать с результатом исправления; исчезновение замечания не считается его закрытием.

`approve` требует `--run`, `--sha256`, `--choice`, `--quote`, `--message-ref`. Аргументы берутся только из показанного пакета и фактического ответа пользователя. Здесь намеренно нет копируемого примера фиктивного одобрения. Правильный хэш или непустая цитата не удостоверяют личность автора сообщения; оркестратор обязан проверить первичное сообщение. То же ограничение относится к идентичности субагента.

`decide` требует `--decision`, `--quote`, `--message-ref`; для `back` дополнительно `--target`. Возврат в G2 снимает активность всех G2 и последующих решений, оставляя их в `history` и `snapshots`. Новая версия проходит ревью и выбор заново. `resume` возобновляет только `hold`; закрытую идею можно пересмотреть явно через `back`/`revise`.

`extend` требует `--through`, `--quote`, `--message-ref` и завершённый предыдущий объём. По умолчанию новый run заканчивается G9; пилот создаётся с `--through G2`. Утверждение дизайна не запускает внешние тесты, производство или выпуск само по себе.

## Память и восстановление

В run хранятся рабочие артефакты, `run.json`, реестр источников, ответы пользователей, отзывы и неизменённые снимки пакетов. Изменение рабочего файла после утверждения будет обнаружено `audit`; верните исходный файл или оформите `decide back` на затронутый этап. Не исправляйте статусы вручную.

`runs/` исключён из Git, чтобы приватные ответы и сведения тестеров не попали в публичный репозиторий. Перед сменой среды сохраните **всю папку run** в доступное постоянное приватное хранилище. Для публичной передачи подготовьте отдельную очищенную копию без личных данных; изменение содержимого требует нового manifest и ревью. Нельзя считать локальный scratch резервной копией.

Если процесс был прерван во время записи, может остаться `.lock`. Сначала убедитесь, что другого писателя нет; только после этого удаляйте оставшийся lock и запускайте `audit`. Запись `run.json` атомарная. CLI не защищает от владельца файловой системы, который согласованно подделает всю историю; это журнал процесса, а не система цифровых подписей.

## Схемы и тестовые данные

Схемы совместимы с JSON Schema Draft 2020-12. Встроенный валидатор проверяет используемое подмножество: `type`, `required`, `properties`, `additionalProperties`, `items`, `enum`, `const`, `pattern`, длины, границы чисел, `anyOf`, `uniqueItems`. Даты и взаимосвязи проверяются дополнительно. Это не универсальная библиотека JSON Schema.

Для обязательных строк CLI дополнительно применяет `minLength` после удаления крайних пробелов: строка из пробелов не считается цитатой или описанием, даже если стандартный валидатор JSON Schema её принимает. Сводка исследования раздельно показывает `source_families_total` (все зарегистрированные источники) и `source_families_used` (источники, на которые ссылаются сигналы).

Синтетические примеры и тесты имеют `is_synthetic: true`. CLI отклоняет их в реальном run. Тесты используют отдельный временный каталог и внутренний тестовый режим; он не включается аргументом CLI. Зелёные тесты подтверждают работу реестра, а не спрос, удовольствие от игры или прохождение пилота.
