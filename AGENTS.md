# AGENTS.md — обязательный маршрут Game Idea Factory

## 0. Что сделать в начале каждого сеанса

1. Прочти этот файл полностью.
2. Прочти `state.md`; для активного прогона прочти `runs/<run-id>/run.json` через `tools/pipeline.py status` — **машинное состояние конкретного прогона авторитетнее проектного обзора**.
3. Прочти `docs/PIPELINE.md`, `docs/ROUTES.md`, `docs/REVIEW_PROTOCOL.md`, `docs/APPROVALS.md`. Для исследования — `docs/RESEARCH_PROTOCOL.md`.
4. Проверь доступность инструментов перед тем, как обещать Godot, Playwright, генерацию изображений, внешний поиск, другие модели или публикацию. Запиши наблюдаемое состояние; выбери согласованный доступный маршрут.
5. Выведи краткий статус: последний подтверждённый этап, текущий материал, открытые блокеры, следующий шаг. Начинай с уже утверждённого решения.

## 1. Цель и границы

Цель — получать проверяемые и оригинальные игровые концепты из культурных и игровых сигналов и постепенно развивать их в **утверждённый полный дизайн первой версии игры**. Публичный выпуск или производство отдельной игры допускается только как согласованное продолжение; этот репозиторий не содержит заранее выбранной игры.

Работай по этапам `G0`–`G11`. Каждый этап производит проверяемый артефакт и карточку одного конкретного решения. Не продолжай через точку утверждения молча. Формулировка «дальше» относится только к заранее явно выбранному единственному варианту.

Пользователь управляет направлением, допустимым риском, полным дизайном и релизом. Агент самостоятельно проводит исследования, прототипирование, технические исправления и тесты **в пределах уже утверждённой работы**. Субагенты дают независимую экспертизу, не принимают решение за пользователя.

## 2. Непереговорные требования

1. **Источник факта.** Для рыночных утверждений храни ссылку, временное окно, регион, тип метрики и уровень достоверности. Не выдумывай метрики, интервью, спрос или тесты.
2. **Независимые свидетельства.** Не считай перепосты и пересказы одной аналитики независимыми источниками. Дедупликация: `source_family`, `cluster_id`, `repost_of`.
3. **Честный статус.** Неизвестные значения остаются `null`/`unknown`; тест с реальными игроками нельзя заменять мнением ИИ.
4. **G2: сравнимые идеи.** Каждая из трёх идей имеет действие, осмысленный выбор, последствие, успех/провал, повод повторить и гипотезу распространения.
5. **G3: реальный A0.** Рабочее управление, обратная связь, завершённый цикл, успех/провал, повтор. Статичный кадр или концепт-ролик не заменяет игру.
6. **G4/G5: одна мутация.** Ветки A1/B1/C1 меняют по одному существенному правилу. Сохраняй A0, сравнивай с ней, откатывай добавление при отсутствии улучшения по выбранной гипотезе.
7. **Ранняя проверка канала.** При G0 выбирается гипотеза канала и экономики, при G2 — предполагаемый повод поделиться, при G5 — дешёвая проверка на реальном игровом фрагменте.
8. **Два уровня согласования.** G2 утверждает основную идею; G9 утверждает полный детальный дизайн первой версии, включая правила, интерфейсы, стиль, прогрессию, объём и критерии качества.
9. **Субагентские ревью.** На G1, G3, G5, G9, G11 назначай независимых проверяющих с линзами `docs/REVIEW_PROTOCOL.md`. Если нет доступных субагентов, фиксируй `BLOCKED`, сообщай пользователю о фактическом ограничении и не имитируй ревью.
10. **Переход только по записи решения пользователя.** Красивый интерфейс, нажатие на офлайн-макете, рекомендация агента или молчание не являются согласием. Никогда не фабрикуй текст пользовательского решения.
11. **Сохранение памяти.** После каждой волны обновляй журнал этапа, `state.md` как обзор, список экспериментов, отклонённые варианты и точку возобновления. Данные активного прогона живут в `runs/<run-id>/`.
12. **Объём разработки.** Каждый новый слой обязан создавать новое решение/значимую эмоцию или улучшать подтверждённую задачу. Решение «не усложнять» допустимо на каждом этапе.

## 3. Маршрутизация

| Ситуация | Обязательный маршрут |
|---|---|
| Новый запрос на идею/тренд | `docs/RESEARCH_PROTOCOL.md` → G0–G2 |
| Выбранное ядро | G3 → G4 → G5; хранить рабочую базу A0 |
| Утверждение концептов, дизайна, релиза | `docs/APPROVALS.md` |
| Передача на независимое ревью | `docs/REVIEW_PROTOCOL.md` |
| Переход к следующей стадии | `python3 tools/pipeline.py audit --run <run-id>` и реальное решение пользователя |
| Полный дизайн и внешний тест | G8–G11 из `docs/PIPELINE.md` |
| Следующий пилот | `docs/PILOT_RUNBOOK.md` |

## 4. Волны и версии

Одна волна = одна ограниченная задача → проверяемый материал → самостоятельный анализ → независимое ревью на отмеченном гейте → исправления → проверка → карточка решения. Не смешивай варианты механик, изменяющие несколько правил сразу. Не заменяй единственный рабочий прототип экспериментом; версии A0/A1/B1/C1 должны восстанавливаться.

После изменения утверждённого G0 или G2 считай зависимые downstream-решения потенциально устаревшими. Обоснуй, что нужно перепроверить; не продолжай по противоречащим состояниям.

## 5. Работа с GitHub

- Перед правкой прочти состояние ветки, `AGENTS.md` и релевантные файлы. Для новых функциональных волн предпочитай отдельную ветку и ревью PR.
- Не модифицируй чужие ветки, незавершённые прогоны или опубликованные результаты, если это не входит в поручение.
- Публичный репозиторий: не коммить секреты, личные данные тестеров, токены, приватные сессии и чужие медиа без прав.
- Исходное discovery сохраняется в `docs/research/`; новые датированные проверки добавляются отдельными версиями, с указанием времени данных.
- Проверяй `python3 -m unittest discover -s tests -v` и `python3 tools/pipeline.py check-repo` перед передачей изменений.

## 6. Когда остановиться

Останавливай переход, если: не предъявлен конкретный материал; выбор между вариантами остался неоднозначным; не получено явное решение; обязательные ревью отсутствуют; есть неразрешённый `critical` или открытый `major`; данные не позволяют сделать необходимый вывод; базовая рабочая версия утрачена; необходимый инструмент недоступен и нет допустимого упрощённого маршрута.

Не создавай искусственную задержку ради согласования каждой команды. Подготовь весь разрешённый результат этапа и предложи одно понятное решение.
