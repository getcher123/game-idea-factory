# Рабочие роли и независимые ревьюеры

Начинай с корневого [`AGENTS.md`](../AGENTS.md), фактического состояния прогона и [`config/routes.json`](../config/routes.json). Эта папка дополняет маршрут конкретными инструкциями для исполнителей и проверяющих. Отдельные роли допустимо исполнять последовательно одним ведущим агентом; обязательные независимые ревью выполняются **разными субагентами**, не авторами рассматриваемого материала.

| Имя в `config/routes.json` | Файл | Что делает |
|---|---|---|
| `orchestrator` | [`orchestrator.md`](orchestrator.md) | Выбирает этап, ведёт решения, назначает проверки, обеспечивает handoff |
| `trend_scout`, `concept_designer` | [`discovery.md`](discovery.md) | Доказательства трендов и три содержательно разные идеи |
| `prototype_builder`, `experiment_analyst` | [`prototype-and-test.md`](prototype-and-test.md) | Играбельный A0, независимые изменения, эксперименты и выводы |
| `art_director`, `distribution_designer`, `systems_designer`, `release_coordinator` | [`product-design.md`](product-design.md) | Подача, распространение, полная система первой версии, выпуск |
| Все имена из `required_reviews` | [`reviewers.md`](reviewers.md) | Независимые критические линзы с отдельными отчётами |

## Контракт исполнителя

1. Получи от оркестратора `run_id`, `gate`, утверждённый scope и ссылки на входные артефакты, включая SHA **предыдущего утверждённого** предложения. На новой стадии собственного `proposal_sha256` ещё нет: его выдаст `propose --manifest` после завершения выходных файлов.
2. Прочти входные материалы и требования соответствующего гейта в [`docs/PIPELINE.md`](../docs/PIPELINE.md).
3. Работай только в разрешённом scope; не меняй другие активные прогоны, утверждённые записи или результаты чужих тестов.
4. Верни реальные выходные файлы в активный прогон и список их путей, известные ограничения, выполненные проверки и открытые вопросы. Непроведённое записывай `not_run`.
5. Передай оркестратору материал для проверки. Только оркестратор формирует proposal manifest и показывает единое пользовательское решение.

## Контракт независимого проверяющего

Получить *завершённый* конкретный материал и его SHA-256, прочитать его самостоятельно, не редактировать, не дописывать и не заполнять пропуски правдоподобными цифрами. Вернуть отдельный отчёт по линзе с реальным `reviewer_id`, доказательствами, вердиктом и рекомендациями. Автор работы не может закрыть её обязательное независимое ревью. См. [`reviewers.md`](reviewers.md) и [`docs/REVIEW_PROTOCOL.md`](../docs/REVIEW_PROTOCOL.md).

## Шаблоны

Шаблоны [`templates/`](../templates/) являются формами для **будущих фактических материалов**. Не переносить их пустые поля в завершённые прогоны как результаты. Общий proposal составляется из manifest и всех файлов, которые пользователь видит и утверждает; MD-карточка сама по себе недостаточна для идентификации полного утверждаемого набора.
