# G4 · Одна мутация правила относительно A0

**Run / версия / автор / выбранный G2:** фактические ID и ссылки на утверждения.
**Утверждённое ядро G3:** путь и хэш рабочей A0, инструкция запуска, проверенное поведение.

## Неизменная база

Прежде чем создавать A1/B1/C1, сохрани восстановимую A0 с исходниками/билдом и записью реального геймплея. Зафиксируй:

- **Базовая петля:** ввод → действие → состояние → обратная связь → исход → повтор.
- **Эмоциональный момент:** что в A0 уже работает, что пока лишь гипотеза.
- **Ограничения:** платформа, длительность, сложность управления, стиль обратной связи, победа/провал.
- **Метрика для проверки:** почему она связана с интересом ядра (например, добровольный повтор или понятность выбора).

## Независимая карточка на каждую ветку A1 / B1 / C1

Создай отдельную копию для каждой ветки, основанной **непосредственно на A0**, а не последовательно на предыдущей мутации.

| Поле | Вопрос |
|---|---|
| `variant_id` / branch / commit / build | Как открыть и проверить именно эту версию? |
| **Одно изменённое правило** | Формула «в A0 ...; в этой ветке ...», без перечня сразу нескольких изменений |
| Сохранённые инварианты | Какие правила, уровни, скорость, управление, обратная связь, аудиовизуальные элементы неизменны? |
| Новое решение игрока | Что теперь можно выбрать, чем различаются действия и их последствия? |
| Эмоция или польза | Почему изменение может усилить напряжение, ясность, удивление или выражение мастерства? |
| Конкретный ущерб | Как оно может испортить понятность, ритм или успешную часть A0? |
| Гипотеза и опровержение | Что должно наблюдаться, чтобы оставить изменение; какой исход означает откат? |
| Цена реализации | Реальное время, техриск, новые зависимости, дополнительные ассеты |
| Ссылка на игровой фрагмент | Как запустить и увидеть эффект без пояснения автора? |
| Путь отката | Как восстановить идентичную A0 и не потерять предыдущие результаты? |

## Контроль перед G5

1. Сравни изменения между A0 и каждой веткой. Если различается больше одного существенного правила, разрежь гипотезу на отдельные независимые варианты.
2. Проверь запуск каждой версии и одинаковые условия сравнения, задокументируй различия оборудования и случайности.
3. Для каждого варианта сформулируй вопрос «может ли изменение не улучшить игру?» и критерий оставить A0.
4. Подготовь [`experiment-plan.md`](experiment-plan.md) **до** сбора результатов. Не называй субъективный прогноз наблюдением игроков.
5. В карточке утверждения предложи ID тестируемых веток и допустимый вариант **«сохранить A0 без мутаций»**.

Новый слой не становится ценным от одного факта его наличия. Если изъятие правила не лишает игрока значимого выбора или эмоции, у него недостаточно оснований войти в первую версию.
