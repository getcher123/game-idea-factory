# G9 · Полный дизайн первой версии / производственный handoff

**Run / версия GDD / авторы / дата / целевая платформа:** реальные идентификаторы и утверждённые ограничения.
**Статус:** предлагается к самостоятельному пользовательскому утверждению G9; одобрение концепта G2 не означает одобрение этого документа.

## 1. След принятых решений

Внеси для **каждого** G0–G8: ID выбранного варианта, `proposal_sha256`, `message_ref` фактического утверждения, соответствующий файл и что нельзя менять без возврата к раннему гейту. Для G3–G5 укажи рабочую A0, выбранную базу после тестов и отклонённые мутации с причинами.

## 2. Обещание и игровой цикл

| Поле | Требование к конкретизации |
|---|---|
| Обещание первой минуты | Что пользователь видит, делает, понимает и почему хочет продолжать? |
| Главный ввод | Кнопки/жесты/курсор с обработкой повторов, ошибок, паузы |
| Состояния и переходы | Полная таблица «состояние → событие → условия → переход → визуальная обратная связь» |
| Правила, ограничения, случайность | Значения, диапазоны и воспроизводимая логика, а не эпитет «сложно» |
| Успех/поражение/рестарт | Явные триггеры, награда/штраф, возврат в цикл |
| Значимый выбор | Какие альтернативы есть, как просчитывается цена решения, что случится без него? |
| Момент эмоции | Что в A0 подтверждено реальным запуском/тестом, что остаётся гипотезой |
| Внеигровое обещание | Повод показать фрагмент другу, условия запуска получателем |

**Инвариант:** первая версия должна быть понятна и интересна в основной петле без прогрессии, наград и социального слоя. Если правило требует другой жанр или меняет утверждённое ядро, вернуться к релевантному гейту.

## 3. Наполнение и глубина

- **Контент первого релиза:** точное число типов препятствий/ситуаций, режимов, уровней или правил генерации; как каждый меняет решение. Где граница MVP?
- **Прогрессия:** что меняется после успешной сессии, как избегается рутина и тупик, есть ли tutorial/fail recovery.
- **Экономика, если утверждена:** источники/траты валют, лимиты, баланс, награды, реклама/покупки, политика несовершеннолетних. Если экономики нет, явно написать «не требуется».
- **Матрица сложности:** параметр → старт → динамика → предел → способ измерить справедливость.
- **Удаляемые слои:** какие механики можно убрать без потери проверенного основного цикла; цена их сохранения.

## 4. UX и художественная спецификация

- **Экранные состояния:** старт, обучение, игра, пауза, успех, провал, рестарт, настройки, деление результатом при наличии.
- **Схема экранов:** навигация, активные/неактивные элементы, физические зоны ввода, адаптивность, доступность и сообщения ошибок.
- **Визуальный язык G6:** конкретные референсы собственного арт-направления, читаемость целей, сигналы выбора и последствий, эффекты.
- **Звук и вибрация:** игровые события, обратная связь, настройки, ресурсы и лицензионные условия.
- **Медиа для распространения G7:** реальный момент геймплея, формат результата, путь получателя, атрибуция приглашения при наличии.

## 5. Реализация и воспроизводимость

| Поле | Что передать производству |
|---|---|
| Технологии и версии | Движок, целевые устройства, реальный способ сборки, внешние зависимости, доступные инструменты |
| Структура и владельцы | Сцены, компоненты, состояния, данные, ассеты, зона ответственности |
| Билды / A0 / вертикальный срез | Пути, SHA/commit, инструкция запуска, запись **реальной** игры |
| Состояние сохранений и сеть | Какие данные живут где, офлайн-поведение, миграция/повтор |
| События аналитики | Триггер, название события, минимальные поля, правила анонимизации, как связывать с гипотезой |
| Права | Происхождение ассетов, лицензии, ограничения на рекламу и коммерческое распространение |
| Задачи и стоимость | Реальные объёмы, зависимости, узкие места, неизвестное, cut-list на случай срока |

## 6. Приёмка первой версии

Для каждой фичи запиши **ID → приоритет → предпосылка → наблюдаемое «готово» → тест/устройство → версия подтверждения → ответственный → статус**. Обязательно проверь: успешный запуск, управление, полный цикл и рестарт, крайние состояния и ошибки, UX ввода, восстановление A0, качество кадров и звука, права ассетов, путь отправленного результата. Незавершённые тесты отметь `not_run`.

## 7. Вопросы и G9-ревью

- **Риски:** неразрешённые вопросы, варианты экономии объёма, предметное решение владельца проекта.
- **Контрсценарий:** какая метрика/ошибка заставит убрать слой, вернуться к G5 или отменить выпуск?
- **Независимые ревью по одному SHA:** `systems`, `production`, `ux`; отдельные reviewer ID, findings, вердикт. После существенной правки — новые отчёты.
- **Вопрос пользователю G9:** утвердить именно этот **полный дизайн первой версии** / вернуть конкретный блок на доработку / пересмотреть прежнее решение / отложить / остановить.
- **Передача G10:** неизменная версия GDD, версия сборки, критерии теста и реальные ограничения. Пользовательское утверждение записать после сообщения, с цитатой и `message_ref`.
