# Manifest предложения · полный пакет одного гейта

**Источник схемы:** [`schemas/proposal.schema.json`](../schemas/proposal.schema.json). Реальный законченный JSON создаётся как `runs/<run_id>/artifacts/<gate>-proposal.json` с **фактическими** значениями текущего прогона. Фиктивный заполненный пример структуры находится в [`examples/proposal-synthetic.json`](../examples/proposal-synthetic.json) и помечен `is_synthetic: true`: **он не пригоден для реального решения пользователя**.

## Обязательные JSON-поля

| Поле | Условие для реального прогона |
|---|---|
| `gate` | Ровно текущий этап `G0`–`G11` |
| `author_ids` | Непустой массив уникальных **фактических** ID агентов-авторов; сверяется с будущими reviewer ID |
| `files` | Непустой массив **существующих** путей относительно `runs/<run_id>/`: все Markdown, JSON/JSONL исследования, визуальные карточки, игровые исходники/билды, записи, документы, нужные для оценки. Пути без `/` в начале и без `..`; **не включай сам manifest** |
| `summary` | Непустое точное описание одного решения, которое требуется от пользователя |
| `options` | Непустой массив объектов с непустыми уникальными строками `id`, `label`: реальные сравнимые варианты выбора; не придумывать варианты ради прохождения схемы |
| `is_synthetic` | `false` **только при настоящих материалах и авторах**; синтетические fixture нельзя утверждать |

## Маршрут исполнения

1. Подготовь настоящие файлы, которые пользователь и независимые ревьюеры будут читать. Заполни manifest. Если фактических материалов нет, оставайся в `draft`/`BLOCKED`, а не создавай искусственный JSON с фальшивыми авторами, файлами или данными.
2. Вызови `python3 tools/pipeline.py propose --run <run_id> --manifest artifacts/<gate>-proposal.json`. Команда валидирует manifest, проверяет пути и вычисляет общий SHA-256 по JSON manifest **и содержимому всех названных файлов**.
3. **Только после `propose`** направь обязательным независимым субагентам точный SHA и пакет; зарегистрируй валидные JSON-отчёты командой `python3 tools/pipeline.py review --run <run_id> --file reviews/<report>.json`.
4. При изменении хотя бы одного файла/manifest зарегистрируй новую версию через `propose` и повтори ревью нового SHA. При отсутствии изменений повторное `propose` после ревью не требуется и может нарушить корректную последовательность состояния.
5. Покажи утверждаемую версию и реальный SHA пользователю. Только его последующее ясное решение с выбранным ID, дословной цитатой и `message_ref` позволяет `approve`. Ни AI-рецензия, ни HTML-клик не заменяют решение.

Дальнейший маршрут пилота останавливается на G2 (`init --through G2`). Отдельное разрешение и `extend --through G9` требуются для запуска G3. Полный порядок: [`agents/orchestrator.md`](../agents/orchestrator.md) и [`docs/APPROVALS.md`](../docs/APPROVALS.md).
