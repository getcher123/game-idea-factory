# Независимое ревью одного SHA · инструкция и поля отчёта

Ревью делает **реальный отдельный субагент** по промпту своей линзы из [`agents/reviewers.md`](../agents/reviewers.md). Автор изучаемого материала не является ревьюером. Ревьюер **читает** зафиксированные файлы, не переписывает их и не принимает решение за пользователя.

Финальный отчёт сохраняется как **валидный JSON** в `runs/<run_id>/reviews/` по [`schemas/review.schema.json`](../schemas/review.schema.json). Эта карточка объясняет содержание обязательных полей, сама по себе Markdown-ревью не проходит CLI.

## Идентичность и границы проверки

| JSON поле | Строгое требование |
|---|---|
| `run_id`, `gate`, `lens` | Реальный прогон, один гейт, линза точно из `config/routes.json` |
| `reviewer_id` | Уникальный ID независимого субагента; не `author_ids` этого предложения |
| `artifact_sha256` | Общий SHA-256 manifest + **всех** файлов, выданный `propose --manifest` |
| `reviewed_at` | Фактическое время ISO 8601 с часовым поясом |
| `is_synthetic` | `false` только если проверка действительно выполнена отдельным субагентом |
| `verdict` | Только `PASS`, `CHANGES_REQUIRED`, `BLOCKED`, `NOT_RUN` |
| `evidence_refs` | Путь/URL/реальный лог, которым проверялись ключевые утверждения |

## Findings — один конкретный дефект на запись

| JSON поле внутри `findings[]` | Содержание |
|---|---|
| `id` | Уникальный ID замечания для разрешения и аудита |
| `severity` | `critical` / `major` / `minor` / `note` |
| `observation` | Что именно неверно, не доказано, не работает или двусмысленно; какой практический ущерб |
| `source` | Точный путь, строка, первичный URL, версия билда/сценарий воспроизведения — **свидетельство** |
| `action` | Проверяемая правка, тест, исключение или вопрос владельцу |
| `resolution` | `open` / `fixed` / `accepted_risk`; результат изменения проверять на новом SHA |
| `risk_acceptance` | `null`, либо **настоящие** цитата и `message_ref` пользовательского принятия риска, без имитации |

## Перед вердиктом ревьюер обязан ответить

1. Все ли файлы из manifest на указанном SHA действительно прочитаны или запущены в нужной степени? Что было недоступно?
2. Какие факты удалось воспроизвести, какие остались гипотезами? Нельзя объявить симуляцию агентом мнением игроков.
3. Где фактический `finding` со ссылкой на свидетельство для каждого серьёзного риска; если дефектов нет — какие проверки реально выполнены?
4. Есть ли открытые `critical` или блокер? При их наличии вердикт не может быть `PASS`.
5. Не участвовал ли ревьюер в создании/правке этих материалов? При самопроверке независимое ревью не закрыто.
6. Если SHA изменился после правки, получен ли новый материал и выполнена ли новая проверка?

Отдельные линзы G1: `evidence`, `market_skeptic`; G3: `game_design`, `ux`, `technical`; G5: `experiment_design`, `game_design`; G9: `systems`, `production`, `ux`; G11: `qa`, `distribution`, `rights`. Вердикт независимого субагента — условие готовности, **отдельное пользовательское решение** всё равно требуется.
