# Карточка решения пользователя · каждый G0–G11

> Одна карточка = одна зафиксированная версия материала + один явный вопрос пользователю. **Содержимое карточки создай до `propose`, если она входит в `files` manifest; после регистрации не редактируй её ради добавления SHA или ревью.** Актуальный SHA и вердикты добавляй в сопровождающее сообщение пользователю, а запись решения храни отдельно в `decisions/`.

## Состояние и доказательства

| Поле | Что указать |
|---|---|
| `run_id`, `gate`, версия | Точный идентификатор прогона, этап и версия предложения |
| Manifest | `artifacts/<gate>-proposal.json` и путь к реальному manifest |
| `proposal_sha256` | Выводится **отдельно при показе** из `propose --manifest`; не вписывать обратно в хэшируемую карточку после регистрации |
| Авторы | Реальные `author_ids` manifest, кто разработал материал |
| Содержание / демонстрация | Ссылки на сравнимые изображения, исследование, запись настоящей игры, playable или GDD |
| Наблюдения | Что действительно известно, со ссылками на исследование/файлы/протоколы |
| Гипотезы и неопределённость | Что ещё не проверено, статус `unknown`/`not_run`, практический риск |
| Независимые ревью, если нужны | В сопроводительном сообщении после `propose`: линза, уникальный reviewer ID, SHA, verdict, открытые findings; отсутствие обязательного ревью = `BLOCKED` |

## Варианты и рекомендация

Для каждого варианта впиши **точный `options[].id` из manifest** и короткий `label`. Сравни по одинаковым критериям: опыт игрока, стоимость следующего шага, измеримый риск, возможность отката. Не показывай как выбор то, чего нет среди `options`.

- **Рекомендую:** один существующий `option.id` и не более трёх аргументов по свидетельствам.
- **Компромисс:** чем пользователь пожертвует при выборе рекомендации.
- **Решение, которое нужно сейчас:** один сформулированный вопрос, на который можно ответить ID или явной командой «доработать / назад / пауза / остановить».
- **Что последует за выбором:** следующий гейт, действия агентов, предел времени/стоимости и что **не** утверждается этим решением.

## Фиксация ответа — **в отдельном файле решения** только после сообщения пользователя

| Поле | Источник и правило |
|---|---|
| `decision` / выбранный `option.id` | Из буквального ответа, без угадывания |
| Дословная цитата | Точный текст пользователя, не пересказ |
| `message_ref` | Проверяемый идентификатор сообщения в диалоге |
| `proposal_sha256` | В точности тот SHA, который пользователь увидел |
| Дата и последствия | Состояние этапа и пересмотр затронутых последующих этапов |

Не проставляй согласие заранее и **не дописывай его в утверждённую карточку**: команда `approve` сохраняет отдельную запись решения. Выбор в HTML, симуляция пользователя, ответ ревьюера и молчание не утверждают материал. Связь с историей обеспечивается `tools/pipeline.py approve` по [`docs/APPROVALS.md`](../docs/APPROVALS.md).
